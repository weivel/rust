The Rust language implementation of weivel, for a host written in Rust that runs plugins written in Rust. It is one of the language implementations the core's `docs/contract/` describes, held to that contract and to the vectors of the conformance kit, and it decides nothing itself: compatibility, order, reach, waiting and revocation are the core's answers, made once in the core so that a Rust plugin meets the very decisions a plugin in any other language meets. It is not the core, and it forces no path, file name, variable or format on its caller. It links no core: the core's binary is loaded at run time from the path the caller gives, so one build of the crate runs against whichever core binary its caller loads, and the crate declares the core's structs and functions by hand rather than generating them, a test holding every struct to what the C compiler makes of the core's header. It is one Cargo package, `weivel-rust`, whose library `weivel_rust` holds one module per module of the contract, under the contract's names; a module named `core` shadows the built-in `core` crate inside the library, which writes `::core::` for that one. The crate has no dependency of any kind. Its `core` module loads the core's binary and owns the one wrapper every call into it goes through; `handles`, `timer` and `context` keep the crate's objects for the core's handles, arm the core's deadline and give each plugin its context; `host` registers, activates, releases and destroys plugins, offers host services, loads C libraries as host services and loads plugins built as libraries of their own across the plugin seam; `standard` reaches the standard's binary, so far its JSON reader and its description checks; and `conformance` drives the kit's layer vectors through the host. The crate is a library and ships no program of its own, so there is nothing of it to run.
